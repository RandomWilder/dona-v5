## The three defects

**(a)** `endsLine` has been on every item since week 3 and nothing read it. `pageLines` is the fold;
pdfjs sets it from `hasEOL`, the OCR adapter maps Document AI's `lines` onto its tokens by text-anchor
range. No geometry — both readers already know, and a third opinion drifts. The demo file carries one
run and zero line marks per page, so (a) alone does nothing for it: the 874 lines come from Document
AI, which is the chain (a) and (b) were designed as.

**(b)** Two copies of one wrong gate — `read.ts` and the intake route — ran OCR only on an empty text
layer, so a phone scanner's layer outranked the real reader. One decision point now,
`readForVerdict`, on the declared type's terms, **before anything is written**; `ocrAfterFile` is
gone. A scan whose OCR text lacks the vocabulary is now *refused*, not filed `unverified` — a
behaviour change, specified before it was coded.

**(c)** A `verification_terms` element is a requirement and `|` separates its spellings.
`תקופת השכירות` keeps one deliberately: it separates a lease from everything else that says הסכם and
הדירה. The policy matrix — every specimen refused in every foreign slot — is green unmoved, and is
the guard against widening a type until it matches anything.

## `batchProcess` was asked for and is not needed

Online `process` takes `individualPageSelector` on a longer document: the demo file, pages 1–3, `200`
in 33.2 s; pages 1–15, `200` with fifteen pages in 36.4 s. batchProcess reads input only from GCS, so
it needed the bytes in a bucket before any verdict — **a staging store, which 3.2, A6 and A12 refuse
and the director's 14 Sep ruling rejected.** The page limit is therefore no longer a refusal; a
**byte** ceiling is, the bound being on the request with the whole file in every one base64-encoded.
The OCR bound went **20 s → 90 s** off the same stopwatch: at twenty the demo file timed out and the
log recorded a reader that had *failed* — a false answer, not a slow one. Failure is now told from
miss by count: `OcrOutcome` is five values, all on the audit line, `pagesRead` beside the page count.

## The corpus is the one file that is not v3's, and why

v3's `evals/corpus.ts` builds its corpus through `occupancy` · `catalog` · `channel` —
`attachDocument`, `ingestDocument`, `chunkLease`, `searchClauses` — so its golden set was graded
against the real ingestion path. v5 has none of that: no agent, no chunker, no document, no module
but `src/scope/`.

The temptation is to lift the harness without a corpus and let the three cases be behavioural. That
fails the acceptance bar rather than meeting it: with nothing that needs a database,
`REQUIRE_POSTGRES` on the evals job gates nothing, and "unset the database URL in CI and watch it go
red" has no way to go red. **The switches are the deliverable**, not the cases.

So the corpus is the smallest thing that is honestly real. Every component is the real one — the
model id and its width come from the `config_settings` rows the running system reads, the embedder is
the real provider client, the ordering is pgvector's own `<=>` over a `vector(1536)` column. What is
authored is the text: nine Hebrew passages in `evals/fixtures/specimen-clauses.ts`, seven lease
clauses and two service-policy sections, holding no real person, building or tenancy. They are not
the דירה להשכיר specimens — those are 1.12's — and swapping them in is a carry.

Two properties of that fixture are deliberate. **No sum of money appears anywhere in it**: foundation
rule 2 is that no tenant-facing price and no balance ever exists, and a fixture is where a habit
starts, so the rent clause states when rent is paid and never how much. And **four of the passages
compete**: §7.2 owner repairs, §7.5 tenant damage, §7.9 common parts and §11.3 utilities all answer
"who pays for this", so a ratchet set against this corpus is set against a corpus where something
else could have won.

**The table is TEMP.** Migrations are one ordered sequence and estate appends from `0004_` at 1.9;
the golden set is not entitled to a row in it. TEMP also means the corpus dies with the connection,
so no run can pass because of what another run left behind — the same discipline `tests/policy/`'s
rolled-back transactions have.

## Half the corpus is provable without a key, and that half has tests

`evals/corpus.test.ts` runs in `npm test`, against a real database, with `createFakeEmbedder(1536)`
injected through the one seam `buildCorpus` exposes. It pins the DDL, the insert and that the order
a search returns is pgvector's and not the insertion order — a passage searched by its own text comes
back first at distance < 1e-6, and the eight distances come back ascending. It also exercises the
refusal path: under the fake embedder an unrelated question is beyond the cutoff, so `ground` returns
`source: 'none'`, `escalate: true` and **no hits at all**.

The gate itself never uses that seam. A golden set graded against a fake embedder grades nothing.
What the seam buys is that the first execution of this file was not on a PR against a paid endpoint.

## The ratchet is measured, and so is the cutoff

`npm run measure` was added to the evals job for exactly two runs and then removed — the ratchet is
set to the rank retrieval achieves *today* (pipeline §7), and the only real embedder in this project
lives in that job, so the number could not be measured on a laptop. Run `33973634637`,
`openai:text-embedding-3-large@1536`:

```
| question                             | expected      | rank | distance | lead over next |
| מי מתקן דוד מים שהתקלקל מבלאי?        | חוזה §7.2      | 1    | 0.4659   | 0.1259         |
| מי אחראי על תיקון דוד המים בדירה?     | חוזה §7.2      | 1    | 0.3109   | 0.1074         |
| מי משלם על נזק שגרמתי לדלת?           | חוזה §7.5      | 1    | 0.4045   | 0.1591         |
| מי מתקן תקלה בחדר המדרגות?            | חוזה §7.9      | 1    | 0.4908   | 0.0170         |
| באילו שעות המשרד פתוח?                | נוהל שירות §2   | 1    | 0.3247   | 0.2738         |
| כיצד מדווחים על תקלה שאינה דחופה?     | נוהל שירות §3   | 1    | 0.3526   | 0.2903         |
| מי זכה בגביע המדינה בכדורגל?          | — (refusal)   | top חוזה §10.3     | 0.7322   |
| מה מזג האוויר מחר בתל אביב?           | — (refusal)   | top נוהל שירות §3   | 0.6922   |
```

**These are observations and not assertions.** `rankAtMost: 1` is what the gate reads; the distances
live here because provider embeddings are not bit-identical between runs and a committed distance is
a gate that fails for weather. The size of that weather was measured too: the same question returned
0.3105 in run `33973510866` and 0.3109 in `33973634637`, a drift of **0.0004** against a winning lead
of 0.1259. The rank is a rank, not a coin flip.

**The first measurement measured the wrong question.** The probe list asked "מי אחראי על תיקון דוד
המים בדירה?" while the case asks "מי מתקן דוד מים שהתקלקל מבלאי?". Both rank §7.2 first, so nothing
was wrong with the ratchet — but an instrument that measures a question the gate does not assert is
an instrument that will eventually disagree with the gate and be believed. The case's own question
leads the probe list now.

**The grounding cutoff moved on the evidence, from 0.62 to 0.59.** It is the only invented number in
the harness — the placeholder refusal rule, replaced by `channel` when that module exists. Five
answerable questions came back at 0.3105–0.4908 and two unanswerable ones at 0.6922 and 0.7322, so
distance separates cleanly here and the gap is `[0.49, 0.69]`. 0.62 sat near its upper edge: 0.129 of
margin above the worst real answer against 0.072 below the nearest false positive. 0.59 is 0.099 and
0.102. With a run-to-run drift of 0.0004 the precision is not the point — sitting in the middle of a
gap rather than at one edge of it is.

## What `evals` costs, and what it can be blamed for

It is a job of its own rather than a step of `gate` for one reason: it is the only thing in this
repository that calls a paid third party. Three provider calls per run — nine passages in one batch,
then one per graded question — on a **CI-only key**, deliberately not staging's or prod's, which live
in Secret Manager and reach only their own service account. This one can be revoked alone without
touching a deployed environment.

Two consequences that were not obvious and are now wired:

- **`release.yml` needed `secrets: inherit`.** The release re-runs this exact workflow against the
  tagged commit through `workflow_call`, and a called workflow inherits no secrets by default. Without
  the line every release would have failed its own evals job on a key it was never handed — first
  discovered by slice 1.10, on the first tag, against prod.
- **A red `evals` now stops staging as well**, for free. `deploy.yml` triggers on the CI workflow's
  *conclusion*, not on a job, so the second job joins the wiring that already made a red commit
  unable to reach staging.

## Observations, which are not assertions

**The refusal margin is thinner than the ranking margin.** For the retrieval case's own question the
runner-up is `נוהל שירות §3` at 0.5917, which is 0.0017 outside the 0.59 cutoff. Nothing asserts it,
and the cutoff is a placeholder — but it says something real about the corpus: a service-policy
section about reporting faults is genuinely near a question about who repairs one. When `channel`
writes the real rule it will need more than a single threshold, and this is the first datum saying so.

**Every answerable probe ranked 1.** Nine passages is a corpus with no room to be wrong in, so these
ranks measure the wiring rather than the retrieval. The number that will mean something is the one
measured against a real chunked lease, and the ratchet is written so that day is a ratchet-down.

**The commit message of `9447ff9` cites the wrong hash** for the commit it reverts — it says
`b6be1c9` where the trip is `b40e02b`. Left uncorrected: fixing it needs a force push, which the bash
guard blocks and which is worse than a wrong hash in one message. The correct pair is recorded here
and in `tasks/todo.md`.

## What this slice carried, and to where

Per pipeline §8 every item is in the entry of the slice that closes it, in both `tasks/todo.md` and
`tasks/roadmap.md` — not only here.

- **→ week 10 (the tenant-facing agent)** — `evals/subject.ts` is a placeholder and says so in the
  file; `runCases` takes a `Subject`, so the real agent replaces it in one line. The same week owns
  `groundingCutoff` and the placeholder `ground()`: the refusal rule belongs to `channel`, and it
  needs to be better than one threshold (see the observation above). The golden set grows from three
  cases toward fifty there.
- **→ week 3 / week 4 (documents and comprehension)** — `evals/corpus.ts` indexes an authored fixture
  into a TEMP table because there is no chunker. When ingestion exists, point `search` at the real
  retrieval path and delete this file's DDL; the ranks are re-measured against a real lease and the
  ratchet moves down, which is what a ratchet is for.
- **→ 1.12 (the corpus)** — the nine authored passages are replaced by the דירה להשכיר specimens the
  day they are in the repo. Also: the CI key means an external model provider now receives text from
  this repository on every PR. It is authored fixture text with no personal data in it, so nothing is
  owed today — but ADR-0004's obligation is to name third parties *before* they see tenant text, and
  1.12 is where that list is written.
- **→ 1.10 (the pipeline round trip)** — the first `v*` tag is the first execution of
  `secrets: inherit`, and the first release whose gate is two jobs. A red `evals` stops the release
  before prod, which is new behaviour that slice will be the first to see.

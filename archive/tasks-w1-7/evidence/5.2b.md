## The acceptance bar, line by line

**Done when: every authenticated screen carries the same bar.**
`tests/ui/tokens.test.ts` — *puts the same chrome on every signed-in screen* — walks the whole
`SCREENS` registry except login and requires buildings, expiring, incomplete, the search GET form,
staff, the sign-out POST, the Hebrew label, and a non-empty `csrf` on that form. The helper is
`signedInChrome` at the composition root; estate, evidence and staff receive it through
`register*Routes` and write none of their own list. Kernel still takes `nav` as HTML.

**Done when: the login screen carries none of it.**
*keeps the login screen without that chrome* — no estate href, no search form, no logout, no יציאה.
The Google link and the add-operator submit use the token `.btn` / `.btn-primary` classes; the local
button skin is gone. Sign-out lives only in the bar, not in the staff body.

## The structural decision

The link list lives beside the index, not in the kernel (routes) and not in `staff/contract.ts`
(estate URLs). `csrfFrom` throws `not_allowed` on a missing or empty token — no `?? ''`. Search in
the chrome is a GET form; the token guard still forbids csrf on GET forms.

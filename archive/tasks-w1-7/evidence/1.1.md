### The ADRs, re-adopted rather than re-argued

Each states the decision, why it carries into v5, and what changes — none reproduces the original
argument. Three carried non-trivially:

- **ADR-0002** — v3 left an open question: whether a citation degrades from a clause to a page when
  numbering cannot be recovered from OCR'd text. **v5 closes it by a different route.** Capture is
  schema-driven (A8) and an `ExtractedField` carries `(page, bbox, confidence, model,
  schema_version_id)`, so a value points at *pixels*. That is stronger than a clause reference and it
  survives a document with no numbering at all. The "schema over templates" framing that ADR deferred
  is settled as A8 and is not reopened.
- **ADR-0003** — v3's week-6 correction (read the key per call, not at instance start) is **the design
  from commit one** in v5. There is no read-at-boot path to retire.
- **ADR-0004** — **status stays `proposed`.** The technical mitigation is decided; the legal basis is
  owed and is not closed by an engineering change. Three things make v5's exposure larger than v3's
  and are recorded in the file: the corpus is 1,500 units rather than one contract and arrives in
  week 1 (R4); OCR hands over whole page images including the front page that clause-reference
  selection withheld (ADR-0002); and week 10 puts a tenant's own question plus their own lease on the
  other end of a model call, which is what redaction must precede.

### Branch protection

Applied to `main` on 4 Sep. It could not be applied earlier: while the repository was private, both
the branch-protection API and the newer rulesets API returned **403 — "Upgrade to GitHub Pro or make
this repository public."** The repository was made **public** instead, and the same call then
succeeded unchanged.

```
$ gh api repos/:owner/:repo/branches/main/protection
{"checks":["gate","evals"],"strict":true,"force_pushes":false,"deletions":false,
 "conversation_resolution":true,"enforce_admins":false}
```

Throwaway PR **#1** (`verify/1.1-protection` → `main`), with no CI in existence to report either
check:

```
$ gh pr view 1 --json mergeStateStatus,mergeable,statusCheckRollup
{"mergeStateStatus":"BLOCKED","mergeable":"MERGEABLE","statusCheckRollup":[]}
```

**`BLOCKED` is the required observation, and it is not the whole answer.** The merge endpoint was
then called directly, and it **merged** — `{"merged":true}`, squash `e143993`. `enforce_admins` is
`false`, and the only account on this repository is an admin, so the gate that blocks the UI does
not block its owner. Measuring that was worth the cost of reverting it.

**`enforce_admins` cannot be `true` yet, and this is a sequencing fact rather than a preference.**
The required contexts are `gate` and `evals`; no workflow exists to report them until slice 1.6
lands `ci.yml`. With admins enforced, a check that never reports blocks every merge *including the
merge of `ci.yml` itself* — the branch protection would make landing the CI that satisfies it
impossible. Slice **1.6**'s own Verify compounds it: it requires pushing a red commit *directly to
`main`* to watch staging refuse it. So the bypass stays open until the checks are real, and
**1.10 carries the owed action to close it**, recorded there rather than only here.

Until then the honest statement of this slice's bar is: a PR to `main` cannot merge without the
required checks **for anyone who is not a repository admin**, and the admin bypass is deliberate,
dated, and has a slice that closes it.

Cleanup: `e143993` reverted by **`29b8a34`**, the throwaway branch deleted locally and on the
remote, `gh api repos/.../branches` lists **`main` and nothing else**. The revert was pushed straight
to `main` — the same bypass, used a second time and noted rather than glossed.

### What going public exposed

The visibility change was a business decision, but it has an engineering consequence, so the tree was
scanned rather than assumed. 52 tracked files: **no secret patterns** (AWS, OpenAI, GitHub, Google,
Slack, PEM, bearer), **no email addresses, no phone numbers**. Nothing in the repo needs to be
rotated. The corpus rule holds by construction — tier 1 is published State documents, and tier 2 was
never here.

What *is* now world-readable is commercial rather than secret: the client is named throughout, and
`docs/stack-map.html` carries vendor unit costs and exit costs, `tasks/plan.md` the risk register,
`tasks/fuses.md` the external dependencies and their status. Worth knowing; not worth undoing on my
own initiative.

One forward consequence, for slice **1.7**: a public repository accepts pull requests from forks.
Workload Identity Federation's `assertion.repository` condition is doing more work than it was on a
private repo, and no workflow may run fork-authored code with that identity — `pull_request_target`
in particular. That belongs in 1.7's design, not in a retrofit.

## Raised, not silently handled

1. **ADR-0004's obligations are not on the fuse table.** The v3 ADR says the DPA and the disclosure to
   data subjects are recorded on `tasks/fuses.md` beside the corpus removal deadline, because they
   share a trigger. v5's `fuses.md` has no such row. It belongs there — but `fuses.md` is the plan's
   file, so this is raised rather than edited inside slice 1.1.
2. **Required check contexts are `gate` and `evals`**, taken from v3's `ci.yml` job names, because
   slice 1.6 lifts that file. If 1.6 renames a job, the protection rule must be updated in the same
   change or every PR blocks forever on a check that will never report. This is now the sharpest
   edge in the repo: the names are load-bearing and nothing yet proves they match.
3. **The admin bypass on `main`**, above. Raised here, owed at 1.10.

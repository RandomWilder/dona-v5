## Bounds

- **pdfjs: 8 seconds.** `AbortSignal.timeout`. Timeout yields **empty pages**, never `unavailable`.
  A later rejection from the parser is swallowed so it cannot take the process down. HTTP: empty
  text layer files as `unverified`, **status 200**. This is the week-3 staging hang: a minute of
  pdfjs became `{"code":"unavailable","message":"unexpected error"}`. Occupying the request for a
  bounded OCR call is acceptable; occupying it for a minute of pdfjs is what week 3 forbade.
- **OCR: 20 seconds.** Same request, after the row exists. A miss, a timeout, or an unconfigured
  processor leaves the row `unverified`. HTTP of that miss is **200**, not 503. Work queue
  (`src/kernel/work.ts`) is **not** wired this slice: the runner is unstarted, and Cloud Run
  `--min-instances 0` would leave jobs sitting until the next request. Extraction (4.2) is when the
  queue gets wired.
- **15 pages online.** Over that, stay `unverified`; do not `batchProcess`.

## What was decided, and why

1. **General OCR processor, location `eu`.** Named in ADR-0002. Form Parser would infer a schema
   this system has already declared. `me-west1` is not a Document AI region.
2. **Two readers, one page shape.** Native text is pdfjs (`confidence: null`). Scan, photograph, or
   empty text layer is Document AI (confidence set). Coordinates from `normalizedVertices` are
   converted once into the same top-down space pdfjs already uses. Images skip pdfjs. Document AI
   accepts PDF and images directly — no rasterizer, no canvas.
3. **OCR on the same request, after the row exists.** A refused upload still writes nothing. A scan
   that OCR cannot finish must not become a 503 on the upload.
4. **No Document AI SDK.** REST + ADC, the same split `objects.ts` made for GCS. `gcloud documentai`
   is a component this SDK does not ship; bootstrap and deploy look the processor up over the same
   REST host the adapter uses.
5. **No fifth OCR ADR.** The processor type and the vendor were already decided.

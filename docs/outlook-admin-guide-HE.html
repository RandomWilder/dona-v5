למה ומה

מערכת דונה פותחת קריאת שירות מכל מייל של דייר. כדי לעשות את זה היא צריכה לקרוא את התיבה שאליה הדיירים כותבים. מתחילים בתיבת פיילוט, ועוברים לתיבה האמיתית רק אחרי שהכל עובד.

  • קוראת: מיילים חדשים בתיבה הנכנסת (Inbox), כל כ-90 שניות, מיום החיבור והלאה. שום דבר ישן לא נמשך.
  • שולחת דבר אחד בלבד: תשובה קבועה עם מספר התורן, כשמייל מסומן כחירום. התשובה יוצאת מהתיבה עצמה ונשמרת ב-Sent Items כמו כל תשובה של המשרד.
  • לא נוגעת: לא מוחקת, לא מעבירה, לא מסמנת כנקרא. התיבה נשארת בדיוק כפי שהיא.
  • תיבה אחת בלבד: ההרשאה ניתנת ב-Exchange ומוגבלת לתיבה הזו. אין למערכת גישה לתיבות אחרות או לרשימת המשתמשים.
הדבר החשוב ביותר: לא להוסיף הרשאות דואר (Mail.Read / Mail.Send) במסך API permissions של Entra. הרשאה שם חלה על כל התיבות בארגון. ההרשאה ניתנת רק דרך Exchange, בשלבים 4–6.

מילוי אוטומטי של הפקודות

אחרי שלב 1 יהיו בידיך שני מזהים. אפשר להדביק אותם כאן, והם ייכנסו לכל הפקודות בהמשך. שום דבר לא נשמר ולא נשלח.

מה צריך לפני שמתחילים

הרשאות מנהל בשני מקומות, ומודול PowerShell אחד.

  • תפקיד Application Administrator (או Global Administrator) ב-Entra.
  • תפקיד Exchange Administrator (או Organization Management) ב-Exchange Online.
  • מודול ExchangeOnlineManagement מותקן:
Install-Module ExchangeOnlineManagement -Scope CurrentUser
  • התיבה asafv@dona.co.il קיימת ופעילה.
1

רישום אפליקציה ב-Entra

יוצרים זהות למערכת דונה, כדי שתוכל להתחבר בלי משתמש ובלי סיסמה של אדם.

entra.microsoft.com ← Applications ← App registrations ← New registration

  1. Name: Dona Platform - Staging
  2. Supported account types: Accounts in this organizational directory only (Single tenant)
  3. Redirect URI: להשאיר ריק.
  4. Register.
  5. בדף Overview להעתיק שני ערכים: Application (client) ID ו-Directory (tenant) ID.
  6. Enterprise applications ← לחפש Dona Platform - Staging ← להעתיק את ה-Object ID משם.
ה-Object ID בשלב 4 הוא של ה-Enterprise application, לא של ה-App registration. אלה שני מספרים שונים, וזו הטעות הנפוצה ביותר בהגדרה הזו.

3

לוודא שאין הרשאות ב-Entra

כל הרשאת דואר ב-Entra חלה על כל הארגון ועוקפת את ההגבלה לתיבה אחת. לכן המסך הזה צריך להישאר ריק.

App registrations ← Dona Platform - Staging ← API permissions

  1. להסיר את User.Read שנוסף כברירת מחדל. המערכת לא משתמשת בו.
  2. לא להוסיף שום הרשאה, ולא ללחוץ Grant admin consent.
  3. התוצאה: הרשימה ריקה.
4

רישום האפליקציה ב-Exchange

Exchange צריך להכיר את האפליקציה לפני שאפשר לתת לה הרשאה. מכאן והלאה הכל ב-PowerShell.

  1. התחברות:
Connect-ExchangeOnline
  1. רישום האפליקציה (המזהים משלב 1):
New-ServicePrincipal -AppId <APP_ID> -ObjectId <ENTERPRISE_APP_OBJECT_ID> -DisplayName "Dona Platform - Staging"
5

הגדרת התחום: תיבה אחת

מגדירים ל-Exchange "תחום" שכולל רק את תיבת הפיילוט. ההרשאות בשלב הבא יחולו רק עליו.

  1. יצירת התחום:
New-ManagementScope -Name "Dona-Staging-Mailbox" -RecipientRestrictionFilter "PrimarySmtpAddress -eq 'asafv@dona.co.il'"
6

מתן ההרשאות על התחום

שתי הרשאות, שתיהן על התחום משלב 5 בלבד. קריאה לקליטת המיילים, ושליחה לתשובת החירום הקבועה.

  1. קריאה:
New-ManagementRoleAssignment -App <APP_ID> -Role "Application Mail.Read" -CustomResourceScope "Dona-Staging-Mailbox"
  1. שליחה (לתשובת החירום בלבד):
New-ManagementRoleAssignment -App <APP_ID> -Role "Application Mail.Send" -CustomResourceScope "Dona-Staging-Mailbox"
7

בדיקה

Exchange יודע לענות אם לאפליקציה יש גישה לתיבה מסוימת. בודקים שהתשובה "כן" לתיבת הפיילוט ו"לא" לכל תיבה אחרת.

  1. תיבת הפיילוט. בעמודת InScope צריך להופיע True בשתי השורות (Mail.Read, Mail.Send):
Test-ServicePrincipalAuthorization -Identity <APP_ID> -Resource asafv@dona.co.il
  1. תיבה אחרת כלשהי בארגון. כאן InScope צריך להיות False:
Test-ServicePrincipalAuthorization -Identity <APP_ID> -Resource <OTHER_MAILBOX>
  1. צילום מסך של שתי התוצאות, לצרף למסירה בשלב 8.
ההרשאות נכנסות לתוקף אחרי 30 דקות עד שעתיים. בדיקה מוקדמת יכולה להראות False גם כשהכל תקין.

כניסה של הצוות עם חשבון Microsoft

עבודה נפרדת מחיבור התיבה, באותו דייר. יוצרים רישום אפליקציה חדש, כדי שעובדי דונה דום ייכנסו למערכת עם חשבון ה-Microsoft שלהם. אין כאן דואר ואין כאן יומן. כ-10 דקות.

לא לגעת באפליקציית התיבה. Dona Platform - Staging נשארת כפי שהיא. לא מוסיפים לה כתובת הפניה, לא מוסיפים לה openid, ולא מוסיפים הרשאת דואר או יומן לרישום החדש.

רישום אפליקציה חדשה

זהות נפרדת, לדייר הזה בלבד. סוג הפלטפורמה הוא Web, כי לאפליקציה יש סוד.

entra.microsoft.com ← Applications ← App registrations ← New registration

  1. Name: Dona Sign-in - Staging
  2. Supported account types: Accounts in this organizational directory only (Single tenant). לא לסמן חשבונות Microsoft אישיים.
  3. Redirect URI: לבחור Web, ולהדביק את הכתובת הראשונה (סביבת הבדיקות):
https://dona-staging-r44j24yuaa-zf.a.run.app/staff/auth/microsoft/callback
  1. Register.
  2. את הכתובת השנייה (פיתוח מקומי) מוסיפים דרך Manifest, לא דרך מסך Authentication: המסך הזה לא מקבל כתובת http עם 127.0.0.1.
    App registrations ← Dona Sign-in - Staging ← Manifest ← בתוך "web", ברשימה "redirectUris", להוסיף את השורה השנייה. התוצאה:
"redirectUris": [
  "https://dona-staging-r44j24yuaa-zf.a.run.app/staff/auth/microsoft/callback",
  "http://127.0.0.1:3000/staff/auth/microsoft/callback"
],
  1. Save. במסך Authentication, תחת Web, מופיעות עכשיו שתי הכתובות.
  2. לא לסמן Access tokens ולא ID tokens תחת Implicit grant and hybrid flows.
  3. בדף Overview להעתיק שני ערכים: Application (client) ID ו-Directory (tenant) ID.
שתי הכתובות חייבות להיות זהות תו-בתו, כולל https מול http, ו-127.0.0.1 ולא localhost. כתובת אחת חסרה או שונה והכניסה נכשלת בשגיאה AADSTS50011.

הרשאות: openid ו-email בלבד

הרשאה מואצלת (Delegated) בלבד, שתי אלה, ושום דבר אחר. לא דואר, לא יומן, ולא הרשאת Application.

App registrations ← Dona Sign-in - Staging ← API permissions

  1. להסיר את User.Read שנוסף כברירת מחדל.
  2. Add a permission ← Microsoft Graph ← Delegated permissions ← לסמן רק openid ו-email.
  3. לא להוסיף Mail.Read, Mail.Send, Calendars.Read, או כל הרשאה אחרת.
  4. לא לעבור ללשונית Application permissions.
  5. ללחוץ Grant admin consent ולאשר, כשברשימה רק שתי אלה. כך עובדי הצוות לא יתבקשו לאשר בעצמם, והכניסה עובדת גם אם הארגון חוסם אישור של משתמשים.
התוצאה ברשימה: openid ו-email, מסוג Delegated, וזהו. הרשאת דואר או יומן כאן אסורה. הדואר נשאר באפליקציה השנייה, ושם רק דרך Exchange.

להמשך

  • התיבה האמיתית: אחרי שהבדיקות עוברות, חוזרים על שלבים 1–8 עבור התיבה שהדיירים מכירים, עם אפליקציה נפרדת (Dona Platform - Production) ותחום נפרד. כך פרטי סביבת הבדיקות לעולם לא יגיעו לתיבה האמיתית.
  • חידוש הסוד של תיבת הדואר: המערכת תתריע 30 יום לפני התפוגה. החידוש הוא סוד חדש ותאריך חדש לאפליקציה Dona Platform - Staging (שלבים 2 ו-8). שום דבר אחר לא משתנה.
  • חידוש סוד הכניסה: אותו דבר לאפליקציה Dona Sign-in - Staging (שלבים 2 ו-4 בחלק הכניסה).
  • ביטול הגישה בכל רגע: מחיקת ה-Client secret ב-Entra עוצרת הכל מיד. להסרה מלאה:
Get-ManagementRoleAssignment -RoleAssignee <APP_ID> | Remove-ManagementRoleAssignment
Remove-ServicePrincipal -Identity <APP_ID>
  • גישה מותנית (Conditional Access): אם יש מדיניות שמגבילה אפליקציות לפי כתובת IP, לעדכן אותנו. המערכת רצה ב-Google Cloud בלי כתובת IP קבועה.

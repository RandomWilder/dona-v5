01 — THE MAP

What the system is made of

The application is ours. Almost everything underneath it is rented. This page exists so that fact is visible before anyone signs anything — and so the four vendors that genuinely matter are separated from the eight that are commodities.

02 — WHAT LEAVES

Which tenant data crosses which boundary

This is the question stakeholders will actually ask, so it is worth answering precisely rather than reassuringly. Two services receive tenant data, for two different reasons, and both are bounded.

The three commitments this rests on. One — all infrastructure sits in me-west1, Google's Tel Aviv region, so the record itself never leaves Israel. Two — the OpenAI account runs under a business agreement with zero data retention and no training on our data; this is a contract term to secure before the pilot, not an afterthought. Three — Meta sees message content and phone numbers because it is the delivery network, exactly as it does for every business on WhatsApp today; it never sees the database.

03 — THE SERVICES

Each dependency, and what it is actually for

Grouped by how much they matter. The platform layer is a commodity; the model and channel layers are decisions.

3.1  Google Cloud Platform

the platform · one vendor, one bill

One account, one invoice, one region. Nothing here is exotic — these are the seven managed pieces that let two people run a production system without anyone administering a server. Each one replaces work we would otherwise do by hand.

Cloud Run

Runs the admin web app, the API, and the agent runtime as containers. Scales to zero overnight and absorbs the morning spike in WhatsApp webhooks without anyone provisioning anything.

COST DRIVES ON: requests · CPU-seconds

Cloud SQL — PostgreSQL

The system of record: buildings, units, tenancies, parties, documents, assets, tickets. High availability, point-in-time recovery, and pgvector for retrieval so no separate vector database is needed.

COST DRIVES ON: instance size · HA · storage

Cloud Storage

Every original document, photo and voice note. Object versioning plus retention lock, so a scanned lease can be superseded but never silently replaced — which is what makes the audit trail meaningful.

COST DRIVES ON: GB stored (tens, not thousands)

Cloud Tasks + Scheduler

The durable timers the whole ticket state machine depends on: SLA clocks, provider offer timeouts, the 24-hour WhatsApp window, nightly document-expiry sweeps. Unglamorous and load-bearing.

COST DRIVES ON: task volume (negligible)

Secret Manager

API keys and WhatsApp tokens, versioned and access-logged. No credential ever lives in the codebase or in an environment file on someone's laptop.

COST DRIVES ON: secrets × access count

Cloud Logging + Monitoring

Operational visibility and the sink for the audit log — every scoped read of tenant data, retained and queryable. Uptime checks and alerting on the same bill.

COST DRIVES ON: log volume ingested

Identity Platform

Admin sign-in with enforced MFA. If Dona Dom is on Google Workspace this collapses into existing staff accounts and costs nothing extra — worth confirming early.

COST DRIVES ON: monthly active admins (few)

3.2  The intelligence layer

two engines, because it is two jobs

Reading a scanned Hebrew lease is two jobs, and the system is better when they stay separate. Getting the marks off the page — printed clauses, a handwritten addition in the margin, a signature, a ticked box, and crucially where on the page each one sits and how confident the engine is about it — is optical character recognition. It is a narrow, measurable problem with a purpose-built engine. Deciding what those marks mean — which number is the rent, which date is the renewal option, whether that margin note changes either — is comprehension, and that is what a language model is for.

Handing both jobs to a vision-capable language model demos well and fails in the place this system cares about most. The data model promises that every promoted field carries a page, a bounding box and a confidence score, so an operator can click a value and see the pixels it came from — and so a dispute a year later has an answer. A language model asked for coordinates will produce plausible coordinates. An OCR engine measures them.

Google Document AI

Third party · the optical layer
What we use it for
  • Full-page OCR of every uploaded document, returning text word by word with a bounding box and a confidence score for each.
  • Hebrew handwriting — the margin additions, corrections and initials that appear on almost every real lease and that general-purpose OCR handles poorly.
  • Signature and checkbox detection — presence and location, not interpretation. "Was clause 14 initialled?" is a question about a mark, not about language.
Why this one

Hebrew print, and Hebrew handwriting far more so, is exactly where OCR engines diverge — and Google's has been the dependable option for scanned Israeli lease documents including handwritten additions and signature blocks. It also sits on the account we already have.

Which processor

The general OCR processor, not Form Parser. We do not need Google to infer the document's structure, because the schema is already declared and the language model does the mapping. That single choice is roughly a twentyfold difference in price for the same outcome.

ALTERNATIVES Azure Document Intelligence · Amazon Textract (weak Hebrew) SWITCHING COST low — image in, text and boxes out BILLING per page processed

OpenAI

Third party · the comprehension layer
What we use it for
  • Language. The reasoning and the drafted messages for all three agents — tenant-facing, provider-facing, admin-facing.
  • Schema mapping. Turning the OCR output — text, positions, confidences — plus the page image into the schema the flow already declared. Extraction proposes; a person promotes.
  • Speech-to-text. Voice notes in Hebrew, Russian, Arabic, French and English. Israeli tradesmen answer in voice notes — this is table stakes, not a nice-to-have.
  • Embeddings. Retrieval over the self-help knowledge base and past resolved calls, stored in the Postgres we already pay for.
Why this one

Strongest Hebrew and Arabic handling of the general-purpose providers, one account covering language, speech and retrieval, and no infrastructure to run. It reads the page image alongside the OCR output — a second opinion on layout and context, rather than the primary reader.

The condition

A business agreement with zero data retention and no training on our data. Without that term this vendor should not be used at all, and the alternative is Gemini on the GCP account already in place — which keeps everything under one contract and one region, at some cost in Hebrew quality.

ALTERNATIVES Google Gemini · Anthropic Claude · Azure OpenAI SWITCHING COST low — and lower now that OCR is a separate stage BILLING usage, post-paid

One flag on this split. Document AI does not run in every Google region, and to the best of our knowledge me-west1 is not among them — processing would land in the EU or US multi-region. If Israeli residency turns out to be contractual rather than preferred, this is the single component on the map that needs an exception, an alternative, or a conversation. Worth confirming before the plan is dated, not after.

3.3  The channel

the one genuinely hard dependency

Meta — WhatsApp Business Platform

Third party · critical path
What we use it for
  • The tenant conversation and the provider conversation — the two threads bound to every service call.
  • Inbound webhooks (messages, photos, voice notes, delivery receipts) and outbound sends.
  • Message templates for anything we initiate outside the 24-hour reply window: a provider offer, an appointment reminder, a document request.
What it needs from Dona Dom

Meta Business verification against the company's legal registration, a dedicated phone number that is not anyone's personal mobile, display-name approval, and each template reviewed before first use.

Why this one

There is no alternative worth discussing. WhatsApp is where Israeli tenants and tradesmen already are, and the entire architecture rests on providers changing nothing about their habits. An SMS or app-based channel would be cheaper and would not be used.

Direct or through a reseller

Go direct on the Cloud API. Business Solution Providers add a per-message markup and a layer between us and the message log for convenience we do not need. Keep a BSP in reserve only if verification stalls.

ALTERNATIVES none credible SWITCHING COST high — but message history stays in our database LEAD TIME 4–6 weeks, bureaucratic

This is the one dependency that can delay the project on its own. Verification is paperwork sitting in a queue at Meta, and no amount of engineering speed compresses it. It should be started the week the project is approved, in parallel with everything else — it is the only item on this page with that property.

3.4  Identity

small service, security-critical

One-time code delivery

Third party · low volume
What we use it for

Binding a phone number to a party the first time they message, and re-binding when a number changes mid-tenancy. Low volume — roughly one code per tenant per tenancy — but it is the hinge the entire isolation model hangs on. Everything downstream trusts this one edge.

Recommendation

Send the code as a WhatsApp authentication template first, SMS only as fallback. The thing we need to bind is this phone's WhatsApp, because that is what will carry every future conversation — so delivering the code through that exact channel proves precisely the right thing, and costs one already-approved template.

SMS fallback covers tenants without WhatsApp and number changes: a local Israeli gateway (Inforu, Cellact) is cheapest for Israeli numbers; Twilio Verify is simpler to integrate and handles code lifecycle for us, at a higher per-message price.

ALTERNATIVES Twilio Verify · Inforu · Cellact · Firebase Phone Auth SWITCHING COST very low — one adapter VOLUME ~1,500 first-time + churn

3.5  Dona Dom's own systems

integration, not procurement

Priority ERP

Dona Dom · existing
What we use it for

Read-only reference: contract ids, customer ids, supplier ids, and balances shown on the admin dashboard. We hold foreign keys and nothing else.

The rule

We never write to it, and money never moves through our platform. Keeping the coupling read-only and thin means an ERP upgrade cannot break tenant service, and our bugs cannot corrupt the books. What is still unconfirmed is what Priority actually exposes and who at Dona Dom owns that access.

The number worth saying out loud. At full scale — 1,500 apartments, five sites, every tenant conversation and every dispatch — the entire external bill lands around the cost of one part-time coordinator. 05 — EXPOSURE

How hard each one would be to leave

A dependency map is only useful if it also says what happens when a vendor raises prices, changes terms, or fails. Ranked by how trapped we would actually be.

VendorLock-inIf it became a problem
Meta — WhatsApp High No substitute channel exists for this market, so the mitigation is not portability but independence: every message, in both directions, is stored in our own Postgres. If access were lost we would keep the complete history and the operation, and lose the delivery mechanism.
Google Cloud Medium Cloud Run is containers and Cloud SQL is ordinary Postgres — both portable. Cloud Tasks is the stickiest piece, and it is a few hundred lines to reimplement. A move would be a project, not a rewrite.
OpenAI Low Provided we keep prompts, tool definitions and evaluations in our own code and refuse any vendor agent framework, swapping providers is changing a client and re-running the test set. Weeks, not months — and lower still because OCR is a separate stage, so a replacement model does not have to match anyone's vision quality.
Google Document AI Low The contract is narrow — an image goes in, text with boxes and confidences comes out — so Azure Document Intelligence is a genuine substitute. The risk here is not lock-in but quality: Hebrew handwriting is the axis on which engines actually differ, and it should be tested on real Dona Dom scans before the choice is fixed.
OTP delivery Low One adapter behind one interface. Genuinely a day's work to replace.
Sentry · email · CI Low Commodities with several equivalent competitors each. Not worth deliberating over.
Priority ERP Medium Not ours to choose — it is Dona Dom's. The protection is the thin read-only coupling: if Priority is replaced one day, one adapter changes and the tenant-facing system does not notice.
06 — NOT BUYING

Services a project like this usually acquires, and won't

The absences on the map are as deliberate as the entries. Each of these would add a licence cost, a seat count, and a second place where the truth lives.

Zendesk, Freshdesk, or any helpdesk SaaSThe ticket and its state machine are the product. Renting a generic one means fighting its data model for the responsibility matrix, the tenancy scope and the two-sided negotiation — the exact things that make this system worth building.
A CRMParties, tenancies and conversation history already live in the record layer. A CRM would be a second, worse copy of it.
A chatbot or conversational AI platformThese sell flow builders and intent trees. Our agent's difficulty is the asynchronous negotiation and the scoped tools underneath it, neither of which a flow builder addresses.
A dedicated vector databasepgvector in the Postgres instance we are already paying for handles this corpus comfortably. Revisit only if retrieval quality — not volume — demands it.
A payment processorMoney stays in the ERP. The platform never holds funds, never quotes a price to a tenant, and therefore needs no processor, no PCI scope, and no reconciliation.
A BI or analytics platformSQL against the record plus the admin dashboard answers the operational questions for a long time. Buy one when someone is actually blocked, not in advance.
An SMS marketing platformUnder חוק התקשורת, service messages and marketing must ride separate rails. Keeping marketing entirely outside this system is the cleanest way to stay on the right side of that line.
Document AI's Form ParserWe buy the general OCR processor and let the language model do the schema mapping, because the schema is already declared before the upload. Roughly twenty times cheaper for the same outcome — the expensive processor solves a problem we designed away.
07 — DECISIONS

What we need from Dona Dom to proceed

Most of these are commercial or administrative rather than technical, and every one of them is faster to start than to finish.

Who owns the Meta Business account and the WhatsApp number?

It must be Dona Dom's legal entity and a company-controlled number — never a developer's account or anyone's personal mobile. Getting this wrong is painful to unwind after templates are approved. Start verification the week the project is approved.

Whose cloud account does this run in?

Dona Dom's own GCP organisation, or ours with the cost re-billed? This decides who holds the data, who can revoke access, and what happens at the end of an engagement. It is easier to answer now than to migrate later.

Is US processing of message content acceptable, with zero retention?

If yes, OpenAI under a business agreement. If not, the model layer moves to Gemini inside the same GCP region — a real quality trade-off in Hebrew, and a decision for Dona Dom rather than for us.

Does data residency in Israel need to be contractual?

The plan puts all infrastructure in me-west1, Tel Aviv. Worth confirming whether that is a preference or an obligation under the tender — it constrains vendor choices if the latter, and Document AI's processor regions are the first place it would bite.

Who is the Priority contact, and what does it expose?

Read access to contracts, customers and suppliers. Until someone confirms what the API offers, the ERP integration stays a plan rather than a schedule.

Is Dona Dom on Google Workspace?

If so, admin sign-in and MFA collapse into existing staff accounts at no extra cost. A one-sentence answer that removes a component from this map.

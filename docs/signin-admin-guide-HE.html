למה ומה

מסך הכניסה של דונה יציג שני כפתורים: Google, כמו היום, ו-Microsoft. כפתור Microsoft מקבל רק חשבון מהארגון של דונה דום, ורק כתובת @dona.co.il. מי שאין לו חשבון צוות במערכת לא נכנס, גם עם חשבון Microsoft תקין.

  • מזהה בלבד: המערכת מקבלת מ-Microsoft את כתובת המייל של העובד ואישור שהוא מהארגון. זה הכל.
  • לא נוגעת: אין גישה לדואר, ליומן, לקבצים או לרשימת המשתמשים.
  • ארגון אחד בלבד: חשבונות אישיים (outlook.com, hotmail) וחשבונות מארגונים אחרים נדחים.
  • נפרד מחיבור התיבה: אפליקציה חדשה באותו ארגון. שינוי בכניסה לא יכול לעצור את קליטת המיילים, וסוד הכניסה לא פותח שום תיבה.
לא לגעת באפליקציית התיבה. DevMail-DonaAi נשארת כפי שהיא. לא מוסיפים לה כתובת הפניה, לא מוסיפים לה openid, ולא מוסיפים הרשאת דואר או יומן לרישום החדש.

מה צריך לפני שמתחילים

הרשאת מנהל אחת, ומשתמש אחד לבדיקה.

  • תפקיד Application Administrator (או Global Administrator) ב-Entra. הוא נדרש גם לאישור ההרשאות בשלב 3.
  • משתמש לבדיקה שכתובת הדואר הראשית שלו ב-dona.co.il. בודקים ב-Entra: Users ← המשתמש ← Properties ← השדה Email.
המערכת קוראת את השדה Email, לא את שם המשתמש לכניסה. משתמש ששם הכניסה שלו ב-dona.co.il אבל הכתובת הראשית שלו ב-onmicrosoft.com יידחה. לבדיקה בוחרים משתמש שהשדה Email שלו מסתיים ב-@dona.co.il.
לכן תיבת הפיילוט של חיבור הדואר לא מתאימה כאן: הכתובת הראשית שלה היא asafv@donail.onmicrosoft.com. זה תקין לקליטת המיילים, ולא משנה שום הגדרה בשלבים הבאים.

רישום אפליקציה חדשה

זהות נפרדת, לארגון הזה בלבד. סוג הפלטפורמה הוא Web, כי לאפליקציה יש סוד.

entra.microsoft.com ← Applications ← App registrations ← New registration

  1. Name: Dona Sign-in - Staging
  2. Supported account types: Accounts in this organizational directory only (Single tenant). לא לסמן חשבונות Microsoft אישיים.
  3. Redirect URI: לבחור Web, ולהדביק את הכתובת הראשונה (סביבת הבדיקות):
https://dona-staging-r44j24yuaa-zf.a.run.app/staff/auth/microsoft/callback
  1. Register.
  2. את הכתובת השנייה (פיתוח מקומי) מוסיפים דרך Manifest, לא דרך מסך Authentication: המסך הזה לא מקבל כתובת http עם 127.0.0.1.
    App registrations ← Dona Sign-in - Staging ← Manifest ← בתוך "web", ברשימה "redirectUris", להוסיף את השורה השנייה. התוצאה:
"redirectUris": [
  "https://dona-staging-r44j24yuaa-zf.a.run.app/staff/auth/microsoft/callback",
  "http://127.0.0.1:3000/staff/auth/microsoft/callback"
],
  1. Save. במסך Authentication, תחת Web, מופיעות עכשיו שתי הכתובות.
  2. לא לסמן Access tokens ולא ID tokens תחת Implicit grant and hybrid flows.
  3. בדף Overview להעתיק את Application (client) ID.
שתי הכתובות חייבות להיות זהות תו-בתו, כולל https מול http, ו-127.0.0.1 ולא localhost. כתובת אחת חסרה או שונה והכניסה נכשלת בשגיאה AADSTS50011.

יצירת סוד (Client secret)

סיסמה נפרדת משל אפליקציית התיבה. המערכת מתריעה 30 יום לפני שהיא פגה, ולכן צריך גם את תאריך התפוגה.

App registrations ← Dona Sign-in - Staging ← Certificates & secrets ← New client secret

  1. Description: dona-signin-staging
  2. Expires: Custom, ל-24 חודשים (המקסימום).
  3. Add.
  4. להעתיק מיד את עמודת Value (לא את Secret ID). הערך מוצג פעם אחת בלבד.
  5. לרשום את תאריך התפוגה שמופיע בעמודת Expires, בצורת YYYY-MM-DD.

הרשאות: openid ו-email בלבד

הרשאה מואצלת (Delegated) בלבד, שתי אלה, ושום דבר אחר. לא דואר, לא יומן, ולא הרשאת Application.

App registrations ← Dona Sign-in - Staging ← API permissions

  1. להסיר את User.Read שנוסף כברירת מחדל.
  2. Add a permission ← Microsoft Graph ← Delegated permissions ← לסמן רק openid ו-email.
  3. לא להוסיף Mail.Read, Mail.Send, Calendars.Read, או כל הרשאה אחרת.
  4. לא לעבור ללשונית Application permissions.
  5. ללחוץ Grant admin consent ולאשר, כשברשימה רק שתי אלה. כך עובדי הצוות לא יתבקשו לאשר בעצמם, והכניסה עובדת גם אם הארגון חוסם אישור של משתמשים.
התוצאה ברשימה: openid ו-email, מסוג Delegated, עם סימון ירוק של Granted, וזהו. הרשאת דואר או יומן כאן אסורה. הדואר נשאר באפליקציה השנייה, ושם רק דרך Exchange.

להמשך

  • סביבת הייצור: כשהיא קיימת, חוזרים על שלבים 1–4 עם אפליקציה נפרדת (Dona Sign-in - Production) וכתובת הפניה של הייצור, בלי כתובת 127.0.0.1.
  • חידוש הסוד: המערכת תתריע 30 יום לפני התפוגה. החידוש הוא סוד חדש ותאריך חדש (שלבים 2 ו-4). שום דבר אחר לא משתנה.
  • הוספת עובד: לא נעשית כאן. מנהל במערכת דונה מוסיף את כתובת ה-@dona.co.il ותפקיד במסך הצוות, והכניסה הראשונה של העובד קושרת את החשבון.
  • ביטול הכניסה בכל רגע: מחיקת ה-Client secret ב-Entra עוצרת את כניסת Microsoft מיד. כניסה עם Google לא מושפעת, וגם לא קליטת המיילים. להסרה מלאה: מחיקת הרישום Dona Sign-in - Staging.
  • גישה מותנית (Conditional Access): מדיניות כמו אימות דו-שלבי חלה על הכניסה הזו כמו על כל כניסה ל-Microsoft, וזה רצוי. אם יש מדיניות שמגבילה לפי כתובת IP או מכשיר, לעדכן אותנו.
